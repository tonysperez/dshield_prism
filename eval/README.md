# Eval set — labeled cowrie sessions

The eval set is what every quality claim in the brutal-review phases
3 and 4 will measure against. Without it, those workstreams reduce to
anecdote.

The set has **two versions** that the eval scripts merge transparently:

- **v1** — stratified random sample. The general-purpose labeled
  corpus.
- **v2** — divergent-pair stress test. Pairs of sessions that share a
  behavior signal (same `playbook_id` or `dominant_intent`) but have
  textually disjoint command sets (`command_set` Jaccard ≤ 0.2).
  Built from the embedding-quality plan E1 to give the embedding's
  "behavior-not-text" claim something to be measured against.

## Files

| File | Status | Tracked? | What it is |
|---|---|---|---|
| `sessions-v1.unlabeled.jsonl` | generated | no | Output of `scripts/build_eval_set.py --mode sample`. Stratified random sample. Not analyst-readable. |
| `sessions-v1/<session_id>.md` | generated | no | Per-session human-readable rendering from `scripts/render_eval_set.py`. |
| `labels-v1.yaml` | hand-edited | yes | The labels — one block per `session_id`. Deliverable. |
| `divergent-candidates.jsonl` | generated | no | Output of `scripts/mine_divergent_candidates.py`. Candidate same-behavior / different-text pairs from the production corpus. Each entry has a stable `pair_id` (`dp-NNN`). |
| `divergent-pairs/<pair_id>.md` | generated, frontmatter hand-edited | yes | Per-pair triage markdown. Top YAML frontmatter carries `decision: pending\|keep\|skip` + `notes:` — the analyst (or `picks-triage-prompt.md` LLM agent) edits those two fields in place. The body below the frontmatter is regenerated by `scripts/render_divergent_candidates.py`. |
| `picks-triage-prompt.md` | hand-written | yes | Self-contained LLM prompt to automate the picks-triage step. |
| `labeling-prompt-v1.md` | hand-written | yes | Self-contained LLM prompt to automate v1 labeling. |
| `labeling-prompt-v2.md` | hand-written | yes | Self-contained LLM prompt to automate v2 labeling — inherits the v1 vocabulary and enforces per-pair independence. |
| `sessions-v2.unlabeled.jsonl` | generated | no | Output of `scripts/build_eval_set.py --mode picks`. Only kept pairs. Each record carries `divergent_pair_id`. |
| `sessions-v2/<session_id>.md` | generated | no | v2 markdown rendering. |
| `labels-v2.yaml` | hand-edited | yes | v2 labels — same schema as v1 plus `divergent_pair_id`. Deliverable. |
| `RUBRIC.md` | hand-written | yes | Labeling rubric (covers both v1 and v2). |
| `baseline.json` | generated | yes | Metric snapshot the CI gate diffs against. |
| `results/` | generated | no | Per-run JSON outputs from `eval_*.py` scripts. |

## Labeling workflow — v1 (general sample)

```bash
# 1. Stratified sample from the live ES (deterministic per corpus + seed)
console/.venv/bin/python scripts/build_eval_set.py --n 300

# 2. Render into per-session markdown + a labels-v1.yaml skeleton
console/.venv/bin/python scripts/render_eval_set.py
```

Then walk `eval/sessions-v1/*.md` one file at a time (any order — they
are independent), read the rendered markdown, and fill the matching
block in `eval/labels-v1.yaml`. Re-running `render_eval_set.py` is
idempotent — existing label blocks are preserved verbatim; new
sessions get empty skeletons appended.

After every ~25 entries, run the validator:

```bash
console/.venv/bin/python scripts/validate_eval_labels.py \
  --labels eval/labels-v1.yaml \
  --unlabeled eval/sessions-v1.unlabeled.jsonl
```

When you're done:

```bash
console/.venv/bin/python scripts/validate_eval_labels.py \
  --labels eval/labels-v1.yaml \
  --unlabeled eval/sessions-v1.unlabeled.jsonl \
  --min-records 200
```

## Labeling workflow — v2 (divergent-pair stress test)

The pipeline is identical to v1 from step 5 onward; the v2-specific
prefix (steps 1–4) drives session selection from the divergent-pair
miner. Each step is deterministic from its inputs, so the whole set
is reproducible from `eval/divergent-pairs/*.md` (the committed triage
decisions).

```bash
# 1. Mine candidates from the production corpus.
#    Stamps a stable pair_id (dp-NNN) on each candidate.
console/.venv/bin/python scripts/mine_divergent_candidates.py
#    → eval/divergent-candidates.jsonl

# 2. Render each candidate pair into a triage MD.
#    YAML frontmatter at top carries decision=pending + notes=''.
#    Body shows both sessions side-by-side with full command streams.
#    Idempotent: existing decision+notes survive re-renders.
console/.venv/bin/python scripts/render_divergent_candidates.py
#    → eval/divergent-pairs/dp-NNN.md, one per candidate.

# 3. TRIAGE — for each MD, edit the frontmatter:
#    a) Hand-triage: open each eval/divergent-pairs/dp-NNN.md, read
#       both sessions, flip `decision:` to `keep` or `skip` per
#       RUBRIC.md's "Picks-stage triage" section, and write a 1-2
#       sentence justification in `notes:`. Don't touch any other
#       frontmatter field or anything below the closing `---`.
#    b) LLM-triage: feed eval/picks-triage-prompt.md to a coding agent
#       (Claude Code / Claude Agent SDK / etc.). The agent reads each
#       pair MD and edits the frontmatter via Edit calls. Manual
#       review of the agent's calls is required — same rule as the
#       labeling agent.

# 4. Materialise the v2 JSONL from the kept pairs.
#    Refuses to run if any MD still has decision=pending.
console/.venv/bin/python scripts/build_eval_set.py --mode picks

# 5. Render v2 markdown + labels-v2.yaml skeleton (reuses the v1
#    renderer; the only v2-specific bit is divergent_pair_id).
console/.venv/bin/python scripts/render_eval_set.py \
  --input eval/sessions-v2.unlabeled.jsonl \
  --out-dir eval/sessions-v2 \
  --labels-yaml eval/labels-v2.yaml

# 6. LABEL each session — Either:
#    a) Hand-label: open each eval/sessions-v2/<sid>.md, read both
#       members of a pair INDEPENDENTLY first, then compare. See
#       RUBRIC.md → `divergent_pair_id` for the three valid outcomes.
#    b) LLM-label: feed eval/labeling-prompt-v2.md to a coding agent.
#       The agent reads eval/labels-v1.yaml (to inherit vocabulary)
#       and writes eval/labels-v2.yaml. Manual review of the agent's
#       calls is required — same rule as the v1 labeling agent.

# 7. Validate (cross-checks divergent_pair_id between YAML + JSONL).
console/.venv/bin/python scripts/validate_eval_labels.py \
  --labels eval/labels-v2.yaml \
  --unlabeled eval/sessions-v2.unlabeled.jsonl
```

See [`RUBRIC.md`](RUBRIC.md) for the labeling rule book, the
"Picks-stage triage" section, the `divergent_pair_id` section, and
worked examples. See [`picks-triage-prompt.md`](picks-triage-prompt.md)
for the LLM agent prompt that automates step 3b, and
[`labeling-prompt-v2.md`](labeling-prompt-v2.md) for the v2-aware
labeling agent prompt that automates step 6b. ([`labeling-prompt-v1.md`](labeling-prompt-v1.md)
is the v1 equivalent.)

## YAML schema (committed file)

The renderer pre-creates one block per sampled session with
`annotated: false` and default-empty fields. Edit the block in place
(open the rendered markdown side-by-side) and flip `annotated: true`
when you're done — the validator only enforces the schema on
annotated blocks.

```yaml
# v1 block — no divergent_pair_id field.
6504648f3ee2:
  annotated:          true                      # flip from false when done
  is_real:            true
  playbook_label:     "ssh_key_chattr_persistence"
  expected_findings:  []
  notes:              "Persistence playbook with recon padding."

d2ab2ca67303:
  annotated:          true
  is_real:            false
  playbook_label:     null
  expected_findings:  []
  notes:              "HTTP request leaked into command-input field; reject."

# v2 block — divergent_pair_id auto-populated by the renderer. Do NOT
# hand-edit; the validator cross-checks it against the JSONL.
1484774d1d8c:
  annotated:          true
  is_real:            true
  playbook_label:     "cred_spray_recon"
  expected_findings:  []
  notes:              ""
  divergent_pair_id:  "dp-001"
```

## Unlabeled JSONL schema (rebuildable, not tracked)

Each line of `sessions-v{1,2}.unlabeled.jsonl`:

```jsonc
{
  "session_id": "<cowrie session_id>",
  "stratum": {
    "size_band": "solo|small|medium|large|unattributed",
    "intent":    "<dominant_intent or 'intent_unknown'>",
    "intel":     "malicious|clean|unknown"
  },
  "rollup_doc":          { /* the prism.rollup.cowrie.session doc, verbatim */ },
  "raw_events":          [ /* cowrie.session.* events, asc by @timestamp     */ ],
  "command_enrichments": [ /* one per unique command line in this session    */ ],
  "divergent_pair_id":   "dp-001"   /* v2 only; absent on v1 records       */
}
```

No embeddings — those get recomputed at eval time from whatever
embedding model is configured then. Stratification axes appear under
`stratum` so downstream eval scripts don't have to recompute them.

Downstream eval scripts (`eval_clustering.py` in 1.3,
`eval_discovery.py` in 1.4) join `labels-v{1,2}.yaml` against the
unlabeled JSONL by `session_id` at load time — the labeled-JSONL file
the earlier plan called for never needs to materialise on disk.
